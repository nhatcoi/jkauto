# apps/desktop — main process / IPC notes

- **Auto-run test harness:** `testrun-auto.handler.ts` handles `TESTRUN_AUTO_START`. Flow: load analysis artifacts → build groups → for each group: AI-generate `.spec.ts`+`.test.yaml` → run each `.test.yaml` via `@jkauto/engine` `runTestCase()` with `screenshotMode: 'final'` → screenshot captured at test end to `.autotest/screenshots/<groupId>/`. Emits `TESTRUN_AUTO_PROGRESS` events during generate+run phases. Returns `TestRunAutoReport` (per-group/per-test results + screenshot paths). Engine `RunOptions.screenshotMode: 'failure'|'final'`; `RunCompleteEvent.finalScreenshotPath` added. UI: `AutoRunPanel.tsx` replaces `TestGenPanel` in `AnalysisView` — gateway config form (apiUrl, frontendUrl, authToken, headless), live progress log with inline screenshot previews, final report with per-test expand/collapse + screenshot viewer.
- **Appium server lifecycle:** `main/handlers/appium.handler.ts` spawns/kills the Appium CLI (`appium --port`). Resolves the bin + a Node-aware PATH via login shell (Electron GUI apps don't inherit shell PATH). `freePort()` kills orphans on the port before spawn; `killAppiumOnQuit()` runs on `before-quit`. IPC: `APPIUM_START/STOP/STATUS/LOG`, `APPIUM_DRIVERS_GET`, `APPIUM_DRIVER_INSTALL`. Logs streamed to renderer (ANSI-stripped) via `APPIUM_LOG`.
- **Appium live inspector session:** `main/handlers/appium-session.handler.ts` holds one live WDA session (independent of test runs) via raw `fetch` to the Appium server. IPC: `APPIUM_SESSION_START/STOP/STATUS/SOURCE/TAP/SWIPE/DEVICES`. Tap/swipe take normalized 0–1 coords → multiplied by device `window/rect`, sent as W3C pointer actions. Devices listed via `xcrun simctl` (iOS) + `adb devices` (Android). Session torn down on quit.
- **Detached inspector window:** `index.ts` `openInspectorWindow()` opens a second `BrowserWindow` loading the renderer with `#inspector` hash (see `main.tsx` routing). Shares the main-process session singleton. IPC: `APPIUM_INSPECTOR_OPEN`.
- **Engine Appium platform:** `engine.handler.ts` injects `APPIUM_HOST/PORT` into profile vars for `platform: 'appium'` test cases and calls `ensureAppiumRunning()` when `appium.autoStart` is set.
- **Custom Playwright browsers path:** `execution.browsersPath` setting (core `app-settings.ts`) → `engine.handler.ts` `applyBrowsersPath()` sets `PLAYWRIGHT_BROWSERS_PATH` before each run-case/run-suite. Fixes web runs failing at 0ms when GUI-launched Electron doesn't inherit the shell env and browsers live in a custom/external dir. UI: `settings/sections/ExecutionSection.tsx`.
- **API test runner:** `platform: 'api'` test cases route to `ApiAdapter` (pure Node `fetch`, no browser). Runner routing fix: `testCase.runner === 'api'` now implies `platform: 'api'` when `testCase.platform` is absent. `ExecutionHelpers` has `setVariable` for cross-step variable passing. New keywords in `engine/keywords/defs/api.ts`: `extract-body`, `set-auth-bearer`, `set-auth-basic`, `assert-header`, `assert-status-range`, `assert-response-time`, `set-variable`, `log-response`. `ApiSession.variables` stores extracted values accessible via `{{varName}}` interpolation in later steps.
- **Profile API Config:** `ProfileSchema` extended with `api?: { baseUrl, defaultHeaders, auth }`. `ApiAdapter.start()` seeds `session.baseUrl`/`session.defaultHeaders` from `profile.api` (fallback: `variables.BASE_URL`). Auth (bearer/basic/api-key) auto-applied to `defaultHeaders`. `EnvManagerDialog` gains "API Config" tab via `ApiProfileForm.tsx`. IPC: `ENV_READ_PROFILE` (full profile), `ENV_WRITE` payload extended with `api` field. `useTestCaseRun` reads full profile and passes `profileApi` in `ENGINE_RUN_CASE` payload.
- **Code analysis source + sync:** `project.json` gains `sourceType: 'git'|'local'` + `sourcePath`. `ProjectSettingsDialog` toggles git URL vs local folder picker. IPC `PROJECT_SYNC` (`project.handler.ts`): local → `syncLocalDir()` copies source to `.autotest/source/` (excludes `node_modules/dist/.git/build/...`), git → returns `repoUrl`. `AnalysisView` shows read-only source badge + **Sync** button (git pull / copy then re-analyze). `analysis.service.ts` `resolveSourceRef` honors `sourceType=local`.
- **Codegraph endpoint accuracy:** `@jkauto/indexer` now extracts Node backend endpoints (express/fastify/koa/nest) via `walkNodeRoutes` + recursive OpenAPI spec discovery (`findOpenApi`), merged with `:id`↔`{id}` param normalization. `autogen-db.ts` `saveKnowledgeGraph` deletes `producer='static' AND status='stale'` nodes after upsert — prevents phantom endpoints/symbols from prior indexes (e.g. switching repo) leaking into the agent knowledge snapshot.
- **Feature bundle for test-gen:** `autogen/feature-bundle.ts` builds a per-feature test dossier so the agent can author 3-4 coherent test cases in one pass. `listFeatures()` groups endpoints+pages by path prefix (auth/users/documents...). `buildFeatureBundle(feature)` returns: endpoints with parsed validation rules (required/minLength/format/enum + sampleValid/sampleInvalid), related UI pages, auth requirement per endpoint (public vs token), seed/test accounts scraped from source (`store/seed/fixture/.env` files → credential records), and suggested scenarios (happy/negative/boundary/auth). Exposed as MCP tools `list_features` + `get_feature_bundle` (`agent/jkauto-mcp.ts`); workflow documented in `agent/prompt.ts`. `getStoredCodeMap` now re-hydrates `request_schema_json`→`requestSchema` so validation survives readback.
- **Harness recording optional in normal mode:** `harness.service.ts` recording fns (`markCompileAndSave`, `recordRuntimeResult`, `recordVerification`, `recordTestPlan`) now no-op when no Directly harness run is active instead of throwing "No active harness run". `validateGeneratedTest` always runs schema validation and only records harness evidence when a run exists. Lets `save_test_case_steps`/`validate_test_case`/`run_generated_test` MCP tools work in normal chat, not just Directly mode.
- **Feature bundle runnable bodies:** `feature-bundle.ts` now emits `sampleRequestBody`/`sampleRequestBodyInvalid` per endpoint (JSON built from validation required fields; seed credentials override login fields → real `{"username":"admin","password":"Admin@123"}`) plus `baseUrlHint` (scans entry/.env for listen port → `http://localhost:3001`). Agent copies these into http-request `expected` + set-base-url step 1, so generated API tests are runnable (no empty body, no unresolved base URL). Guidance in `agent/prompt.ts` test-gen workflow.
- **Endpoint query/path params:** `code_endpoints` gains `parameters_json` (migration ALTER for existing DBs). `getStoredCodeMap` re-hydrates `parameters`. `feature-bundle.ts` exposes `parameters` per endpoint + `samplePath` (required query params filled, e.g. `/search?q=test`; path params `{id}` left literal for substitution). Agent uses samplePath as the http-request URL so required query params aren't dropped (was causing 400 "querystring must have required property 'q'"). Guidance in RULES['test-generation'].
